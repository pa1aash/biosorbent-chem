# docs/ — Governing project documents

## What belongs here

- `00_SPEC.md` — the build specification distilled from the Report Bible. The authority on WHAT THE REPORT MUST BE.
- `01_ATTACK_REGISTER.md` — live referee attack-surface issue register.
- `02_PROTOCOL_AUDIT.md` — audit of the executed protocol against the spec and the outline's claims.
- `03_DECISIONS.md` — dated decision log; every judgement call Palaash made, with rationale.
- `EXPERIMENTAL_PROTOCOL_v2.md` — the corrected protocol at report-Methods granularity; source text for Section II.
- `DATA_REQUEST.md` — the definitive list of datasets required, with schemas.
- `GAP_REGISTER.md` — open gaps between what the report needs and what exists.

## What must never go here

- Report prose. Section text lives in `report/sections/`.
- Numeric results. Every number lives in `data/CANONICAL_NUMBERS.yaml`.
- Anything generated by a script — those belong in `data/processed/`.
